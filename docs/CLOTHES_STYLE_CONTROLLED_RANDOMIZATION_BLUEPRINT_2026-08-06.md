# 服装风格配方与可控随机化蓝图（2026-08-06）

## 1. 记录目的

本文件记录当前关于“让随机种子生成具有明确服装风格”的核心结论，作为后续服装、鞋子、帽子和盔甲资产工作的长期蓝图。

当前目标仍然是为 Q 版 Actor 建立可靠的游戏资产，不提前承诺支持任意人形或任意服装风格。

## 2. 核心结论

不能让随机种子单独决定服装风格。随机种子必须受一个明确的风格配方约束：

```text
风格标签 -> 参数范围 -> 可复现随机种子 -> 资产生成 -> 适配检测 -> Gallery 审核
```

因此，随机池中保存的不是无法解释的随机网格，而是：

- 风格 ID；
- 服装模板 ID；
- 参数范围和禁止条件；
- 随机种子；
- 目标 Actor 和支持的动作范围；
- 适配检测与人工审核结果。

只有通过静态、四方向、动作和遮挡验收的完整服装包，才能进入运行时随机池。

## 3. 风格配方的五层参数

每个风格由以下五层组成：

1. **轮廓**：紧身/宽松、短款/长款、衣摆宽度、整体体积。
2. **结构**：领口、袖型、裤型、口袋、腰带、衣片组合。
3. **材质**：布料、皮革、金属、毛皮等，以及厚度和硬挺程度。
4. **装饰**：扣子、肩带、徽章、边缘、护片和挂件。
5. **配色**：主色、辅色、金属色、明度和对比度范围。

风格标签只负责选择这些参数的范围，不能绕过 Actor 拟合、骨骼绑定和穿模检查。

## 4. 推荐工具分工

### 4.1 软质服装

GarmentCode 继续作为服装结构生成的主要候选。它支持参数化缝纫版型、可替换服装组件和可复现设计参数，适合通过同一模板产生不同长度、宽松度、袖型和领口的变体。

参考：

- [GarmentCode 官方仓库](https://github.com/maria-korosteleva/GarmentCode)
- [GarmentCode 参数化服装研究](https://arxiv.org/abs/2306.03642)

### 4.2 刚性或半刚性部件

Blender Geometry Nodes 用于生成腰带、扣件、口袋、护甲片、鞋底和装饰条等程序化部件。部件应绑定到骨骼锚点或局部适配笼，不使用软布料模拟解决盔甲问题。

参考：[Blender Geometry Nodes 官方文档](https://docs.blender.org/manual/en/dev/modeling/modifiers/generate/geometry_nodes.html)

### 4.3 材质与配色

Blender 材质节点负责把同一套几何结构转换为布料、皮革、金属等视觉风格。材质随机化必须独立于几何随机化，避免一个不可控的 seed 同时改变轮廓、穿着方式和颜色。

### 4.4 概念到版型的研究方向

Design2GarmentCode 代表“设计概念转为参数化服装程序”的研究方向，可以作为未来自然语言风格描述的参考，但目前不作为项目生产依赖。

参考：[Design2GarmentCode 研究项目](https://arxiv.org/abs/2412.08603)

## 5. 风格配方示例

下面的示例表示参数意图，不代表当前已经实现的生成器：

```yaml
style: miner
template: base_short_sleeve
silhouette: loose
length: medium
sleeve: short_or_rolled
collar: small_round
pockets: many
belt: enabled
material: heavy_cloth
palette: brown_gray
forbidden:
  - hem_below_pelvis
  - sleeve_inside_hand
  - body_penetration
```

初期建议建立以下风格配方：

- `base_short_sleeve`：基础短袖，作为结构和检测基线；
- `miner`：厚重短衣、工具腰带、护膝、深色布料；
- `hunter`：皮革、肩带、口袋、护腕、自然色；
- `mage`：宽松衣身、宽袖、高领、腰带、饰边；
- `pirate`：宽松上衣、腰封、长靴、头巾、红黑或棕色配色。

这些配方应先复用已验证的基础结构，再逐步增加结构差异，不能一开始同时改变衣长、袖子、领口、材质和配件。

## 6. 种子与资产包规则

建议使用稳定的组合键：

```text
seed = hash(style_id, template_id, actor_id, variant_index)
```

同一个 seed 在相同版本的生成器中必须得到相同的参数组合。版本升级后应保存生成器版本，避免历史服装包无法复现。

运行时随机化只选择已验收的整体 bundle，不随机拼接未经验证的衣片。整体 bundle 可以包含：

- 上衣或外套；
- 下装；
- 鞋子或靴子；
- 帽子、头盔或头部配件；
- 材质和配色方案。

## 7. 当前阶段边界

当前只针对 Q 版 Actor 建立第一版配方和参数。为了未来扩展到其他人形，参数命名应尽量使用局部相对量，例如肩宽比例、躯干长度比例、脚长比例和骨骼锚点，而不是硬编码绝对坐标；但暂不为其他身体实际制作适配器。

当前不采用以下路线作为生产核心：

- 让文本到图像模型直接输出可绑定的服装网格；
- 让单个随机 seed 同时决定几何、材质和穿着层级；
- 把未通过四方向和动作检查的局部网格直接加入运行时随机池；
- 继续寻找一个声称能统一生成所有衣服、鞋子和盔甲的万能插件。

## 8. 后续实施顺序

1. 固定当前短袖基线和 Actor 适配检测。
2. 将短袖参数整理成第一个 `base_short_sleeve` 配方。
3. 只改变配色和少量装饰，验证 seed 可复现。
4. 再增加矿工、猎人等结构风格配方。
5. 独立建立鞋子、帽子和盔甲的刚性模块生成器。
6. 通过 Gallery 审核后，才把风格 bundle 纳入运行时随机化。

本蓝图不等于已经完成风格生成器；它定义的是后续实验必须遵守的参数边界、工具分工和验收顺序。
