# 发型设计、随机池与评审页面设计

## 1. 目标

将当前“整体发型工作台”和“组件装配工作台”的概念合并为一个发型设计/评审页面。页面以组件槽位为中心，支持：

- 每个部件从随机池随机挑选；
- 每个部件从随机池手动挑选并锁定；
- 保存当前组件组合和设计元数据；
- 未来接入像素化预览、多方向预览和预览文件保存；
- 从随机池抽取部件作为种子生成组合，交给评审人接受或销毁；
- 查看只包含随机池内容的 Gallery。

页面不再用“整体随机化 / 组件随机化”拆成两个工作台。整体发型是组件槽位的一种组合结果，组件随机和手动选择共用同一套页面状态。

## 2. 组件槽位

所有组合首先满足兼容矩阵和 base 约束：

| 槽位 | 是否必选 | 随机来源 | 说明 |
|---|---:|---|---|
| `base` | 是 | 随机池或手选 | 女性使用 `Chloe_hair_back_01` 作为底座；男性使用 `Colin_hair_base_01/02`。|
| `front_bangs` | 否 | 随机池或手选 | 前发/刘海。|
| `side_coverage` | 否 | 随机池或手选 | 侧发、鬓角和侧面覆盖。|
| `back_section` | 否 | 随机池或手选 | 男性后脑发段，不能替代 base。|
| `back_attachment` | 否 | 随机池或手选 | 丸子、双马尾连接件和后部装饰，只能叠加在兼容底座上。|

女性当前没有独立命名的 `back_section`，`Chloe_hair_back_02/03` 按后部附件处理；男性 `Colin_hair_base_01/02` 是 base，`Colin_hair_back_01..05` 是后脑发段。

槽位配置必须包含 `gender`、`role`、`selection_mode`、`component_id` 和 `locked`。其中 `selection_mode` 只有两种：

- `random_pool`：从当前性别、当前角色且状态为 `pool` 的组件中随机选择；
- `pool_pick`：从同一随机池中手动选择，并锁定该组件。

预定义发型不是随机池成员。它是保存后的设计组合，只能通过“手选已知组件”或“载入设计”使用，不得被随机池随机抽中，也不得出现在随机池 Gallery。

## 3. 统一设计页面

页面建议保持一个手机可用的纵向流程：

1. 选择性别和设计名称；
2. 逐个槽位选择“随机池随机”或“随机池手选”；
3. 点击“生成组合预览”；
4. 查看正面、侧面、背面和左侧预览；
5. 点击“保存设计”；
6. 将当前组合送入“种子评审”或返回随机池 Gallery。

页面中的“随机”按钮只重新随机未锁定槽位。锁定的手选组件必须保持不变，base 没有有效选择时不允许生成。

页面只保留一个“生成组合预览”按钮，并配合“随机未锁定：开/关” Toggle：开启时生成按钮先重抽未锁定槽位，关闭时生成按钮完全使用当前手选结果。这样手选和随机共用同一个生成入口。

保存设计时记录组合，不把它自动加入随机池。这样可以区分：

- `preset`：评审人认可的预定义组合；
- `draft`：尚未完成预览或尚未评审的临时组合；
- `pool_candidate`：等待评审是否加入随机池的候选；
- `pool`：已被评审人加入随机池的单个组件。

## 4. 组件保存和预览数据

设计记录建议采用以下结构：

```json
{
  "schema": "assetslab_hair_design_review_v1",
  "design_id": "design_female_001",
  "gender": "female",
  "seed": 1042,
  "slots": {
    "base": {
      "selection_mode": "pool_pick",
      "component_id": "female_base_cap:Chloe_hair_back_01",
      "locked": true
    },
    "front_bangs": {
      "selection_mode": "random_pool",
      "component_id": "female_front_bangs:Chloe_hair_bangs_03",
      "locked": false
    }
  },
  "preview": {
    "raw_four_view": null,
    "pixel_four_view": null,
    "saved_at": null
  },
  "lifecycle": "draft"
}
```

`preview` 先允许为空。当前如果没有自动合成和渲染，就只保存 JSON 组合，不创建伪预览，也不执行自动销毁。未来接入 Blender 合成后，再将生成目录、四方向图、像素图和 manifest 写入该字段。

## 5. 种子随机生成与评审

第二阶段从随机池中抽取组件作为种子生成组合：

1. 仅从 `pool` 状态组件抽取；预定义设计不参与抽取；
2. base 始终先选择，再按兼容矩阵选择其他槽位；
3. 记录随机种子、所有组件 ID 和生成参数；
4. 生成四视图预览，未来再追加像素化预览和多方向动画帧；
5. 评审人选择“加入随机池”或“销毁”。

“加入随机池”针对被评审的组件候选，而不是把整个组合无条件变成随机池成员。若评审人认可的是整套搭配，应点击“保存设计”，将它保存为 `preset`；若认可的是某个新后发或刘海，则将该组件候选写入对应角色的 `pool`。

当前没有自动合成时：

- 不创建定时销毁任务；
- “销毁”按钮暂时只删除手动生成的候选记录和对应输出目录；
- 已保存设计和已加入随机池的组件不可被临时清理操作删除；
- 后续实现自动合成后，再给 `pool_candidate` 增加 TTL 和定时清理。

## 6. 随机池 Gallery

随机池 Gallery 是统一页面中的独立区域或 Tab，但数据源必须和预定义设计分离：

- 只显示 `lifecycle=pool` 或 `pool=true` 的组件；
- 不显示 `preset`、`draft` 和历史整体发型页面中的预定义组合；
- 每张卡显示性别、组件角色、组件 ID、来源文件、预览图和加入时间；
- 支持打开预览、查看四方向结果（未来追加）、销毁随机池成员；
- 销毁前显示角色和组件 ID，避免误删 base；
- base 组件可以标记为受保护，删除前需要额外确认。

随机池 Gallery 与设计页面共享组件记录，但不共享预定义组合列表。这样评审人看到的“随机池”就是未来 NPC 随机化真正可能抽到的内容。

## 7. 与游戏运行时的关系

组件随机化主要用于离线扩充随机池和生成预定义设计。游戏运行时仍建议从通过验收的整体发型 bundle 中随机选择：

```text
离线组件随机 → 评审 → 加入随机池 → 固化为整体 bundle → 世界生成按 seed 选择 bundle
```

世界生成阶段使用 `world_seed + npc_id` 计算稳定的 bundle ID，选择成本为 O(1)。NPC 共享网格、材质和纹理，不在运行时执行 Blender 或几何贴合。只有在小规模 NPC 或已经缓存的组件组合中，才考虑运行时按组件装配；否则会增加节点和绘制调用。

## 8. 实现顺序

按以下顺序逐项实现，每一步都先生成静态预览再扩大范围：

1. 统一数据模型：增加 `pool / preset / draft / pool_candidate` 状态和 `selection_mode`；
2. 重构当前工作台为统一组件页面，去掉两个模式 Tab；
3. 实现 base 必选、各槽位随机池随机和随机池手选；
4. 实现设计保存，先保存 JSON 和已有预览路径；
5. 实现种子组合生成、候选评审、加入随机池和手动销毁；
6. 实现随机池 Gallery，明确排除预定义设计；
7. 接入四方向、像素化和未来动画帧预览；
8. 将通过验收的组合固化为游戏运行时 bundle。

## 9. 验收标准

- 任何组合没有 base 时都不能生成；
- “随机池随机”不会抽到预定义设计；
- “随机池手选”只显示对应性别和角色的 pool 成员；
- 保存设计不会自动污染随机池；
- 随机池 Gallery 不出现预定义内容；
- 未自动合成阶段不会误删已保存设计或正式随机池成员；
- 每个候选可追溯到 seed、组件 ID、来源 Blend 和生成 manifest；
- 未来接入像素化时，保存记录能同时关联 raw、pixel、四方向和动画帧预览。
