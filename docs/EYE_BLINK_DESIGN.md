# 移动中的眨眼设计记录

更新时间：2026-08-05

## 结论

应该做，但应作为独立的小型表现层实验，不应修改当前 4 方向 × 8 帧的身体动画合同。

眨眼对大头角色的表情收益高，且只需要替换眼睛图层；不过在 64×64 下，眼睛必须先从 Actor V1 的 Blend 内嵌贴图中拆成方向化透明 Face 层，否则无法稳定地在 Godot 中替换。

## 推荐实现

- 每个方向准备 `open`、`half`、`closed` 三种眼睛状态；第一版也可以只使用 `open` 和 `closed`。
- 眨眼只改变 `Face`/`Eyes` 层，不改变 `Head`、身体帧、脚底基线或锚点。
- 眨眼帧索引独立于行走帧索引；角色移动时仍连续播放身体 8 帧循环。
- 使用稳定的角色 seed 生成眨眼间隔，避免录制、回放和测试时出现不可复现差异。
- 默认间隔约 2.5–5 秒，闭眼持续 1–2 个显示 tick；攻击、受伤、对话等特殊状态以后可以覆盖普通眨眼。

推荐序列：

```text
open → half → closed → half → open
```

第一阶段只做正面和右侧面，确认像素可读性后再补背面/左侧面。背面不一定需要可见眨眼，可以保持 `open` 或透明 Face 层。

## 验收标准

1. 眨眼不造成头部、耳朵或发型跳动；
2. 行走帧不重置，方向切换不丢失眨眼状态；
3. 同一个 seed 的间隔和帧序列一致；
4. 1× 和游戏实际显示尺寸下都能看出闭眼，而不是随机噪点；
5. headless 测试可以输出一次固定 seed 的眨眼序列。

## 暂不做的方案

当前不建议先给 Blender 角色增加复杂面部骨骼、Shape Key 或真实眼睑网格。它们会把已稳定的头部绑定重新变成高成本 3D 变形问题；对于当前像素目标，独立眼睛/眼睑 PNG 层更可控。
