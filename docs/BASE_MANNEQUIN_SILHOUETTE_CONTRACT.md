# Base Mannequin 轮廓合同

## 目标参考

最终角色轮廓以项目根目录的
`base-mannequin-4way-female-sheet.png` 为静态四方向参考，以
`walk-base-4way-female-4frame-sheet.png` 为行走姿态和脚步节奏参考。

四方向顺序固定为：

```text
front → right → back → left
```

这两张图是轮廓与比例参考，不要求直接作为最终运行时贴图。

## 必须保留的轮廓特征

- 头部可以偏大，但头部下方必须有清晰、稳定的颈部过渡；
- 肩膀、躯干、臀部和大腿要形成连续的 Q 版体块；
- 手臂和手掌必须从躯干轮廓中读出来，不能缩成一条线；
- 双腿必须有可辨认的大腿、小腿和脚掌体积；
- 正面和背面要保持左右对称，侧面要保留腹部、臀部和脚掌的前后关系；
- 四方向脚底要保持同一基线，动作帧不能让角色整体上下漂移；
- 在 64×64 运行尺寸下，躯干、手臂、腿和脚仍需可辨认。

## 当前候选判定

`chibi_base_mesh_accurig_diagnostic` 的像素包已经通过资源读取、Godot 播放和原型接入测试，但它没有通过本轮轮廓合同：

- 头部相对躯干过大；
- 躯干和四肢过窄，手脚细节在 64×64 下基本消失；
- 当前结果更像绑定/投影诊断，不像 `base-mannequin-4way-female-sheet.png` 的中性 Q 版素体。

因此它的状态是：`pipeline_baseline_only`，不是 `silhouette_approved`。

## 下一轮实施顺序

1. 以女性 base mannequin 的正面、侧面、背面轮廓建立 3D 素体比例检查；
2. 优先修正躯干、手臂、腿和脚掌体积，不先做五官；
3. 重新做四方向中性站立渲染，先过轮廓合同；
4. 再把走路动作迁移到通过轮廓检查的演员；
5. 最后重新生成 64×64 像素资源并运行完整闭环。

技术闭环仍然保留，用来验证流程是否可运行；轮廓合同则决定资源是否可以进入下一阶段。
