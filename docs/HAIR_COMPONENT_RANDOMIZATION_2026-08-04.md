# 发型组件分类与随机化策略

## 结论

当前采用“两层随机化”方案：

1. 默认流程继续使用已经通过正面、侧面、背面和像素化检查的完整发型种子。
2. 组件随机化作为受约束的扩展层，只从兼容的前发、侧发、完整后发壳和后部附件中组合。

初始比例建议为完整发型 80%、组件变体 20%。这是便于稳定验证的起始策略，不是永久限制；组件池和验收数据稳定后再逐步提高组件变体比例。

## 组件角色

组件不按上传文件名作为池名，而按在演员头部的职责分类：

- `front_bangs`：额头和前脸轮廓的前发/刘海。
- `side_coverage`：侧面覆盖、鬓角和侧发。
- `complete_back_shell`：覆盖头顶和后脑勺的完整底座，可以作为一套发型的主体。
- `back_attachment`：丸子、双马尾连接件或后部装饰，只能叠加在完整后发壳上。
- `base_cap`：源文件里的底层帽/头皮覆盖件，未经四视图检查不进入默认随机。
- `experimental_back_shell`：目前有白缝、露头皮或覆盖不完整的后发件，只保留在审查池。

完整清单见 `prototype/assets/hair/hair_component_catalog_v1.json`。

## 当前分类判断

女性 Chloe 素材中，`Chloe_hair_back_01` 是当前确认的完整后发壳；`back_02/03` 更接近丸子或后部附件，不能独立替换；`back_04..09` 仍属于实验后发。男性 Colin 素材中，`back_01..05` 进入基础后发池，`back_06` 保留为已知不完整实验件；8 个刘海素材确实存在差异，但现有组装的共用顶/后壳会把差异遮住。

## 推荐生成顺序

组件候选应按下面顺序处理：

`演员头部锚点 → 后发完整壳 → 侧发 → 前发/刘海 → 后部附件 → 接缝与耳朵检查 → 四视图像素化检查`

不能直接做任意 `front × side × back`。每个组合还需要记录性别、发型角色、深度层级、耳朵关系和是否允许替换完整底座。

男性刘海当前的主要问题不是资源不存在，而是深度层级：孤立的 `Colin_hair_bangs_08` 可以覆盖额头，但和共用侧/后发组装后会被壳体遮挡。因此男性刘海应先建立独立的前发深度校正和组合审查，再进入推荐池。

## h.art 式贴合流程的复用方向

可以复用之前处理发型时的思路，但将它明确成可重复流程：

1. 以演员头部和耳朵为唯一空间锚点，不以源发型原点为准。
2. 按 `base / back / side / bangs / attachment` 分层导入并分别校准位置、比例和前后深度。
3. 对需要遮盖头皮的完整后发壳做表面贴合；附件只做局部贴合，不能用附件承担整块头皮覆盖。
4. 对侧面设置像素补偿和白缝检查，最后再跑四方向、动画帧和 Gallery 预览。

这套流程适合组件随机化，但每个新组合都必须先成为独立候选，不能直接绕过审查进入随机池。
