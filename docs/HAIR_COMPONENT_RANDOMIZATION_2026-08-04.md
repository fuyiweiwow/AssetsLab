# 发型组件分类与随机化策略

## 结论

当前采用“两层随机化”方案，并把 base 作为装配前置条件：

1. 默认流程继续使用已经通过正面、侧面、背面和像素化检查的完整发型种子。
2. 组件随机化作为受约束的扩展层，先选择必选 `base_cap`，再从兼容的前发、侧发、后脑发段和后部附件中组合。

初始比例建议为完整发型 80%、组件变体 20%。这是便于稳定验证的起始策略，不是永久限制；组件池和验收数据稳定后再逐步提高组件变体比例。

## 组件角色

组件不按上传文件名作为池名，而按在演员头部的职责分类：

- `front_bangs`：额头和前脸轮廓的前发/刘海。
- `side_coverage`：侧面覆盖、鬓角和侧发。
- `base_cap`：组件装配的必选底层。女性用 `Chloe_hair_back_01` 承担该职责；男性使用 `Colin_hair_base_01/02`。
- `back_section`：男性后脑发段，必须叠加在 base 上，不能替代 base。
- `back_attachment`：丸子、双马尾连接件或后部装饰，只能叠加在完整后发壳上。
- `base_cap`：源文件里的底层帽/头皮覆盖件，未经四视图检查不进入默认随机。
- `experimental_back_shell`：目前有白缝、露头皮或覆盖不完整的后发件，只保留在审查池。

完整源组件清单见 `prototype/assets/hair/hair_component_catalog_v1.json`；当前允许随机抽取的成员见 `prototype/assets/hair/hair_random_pool_v1.json`。实验组件不会自动进入随机池。

## 当前分类判断

女性 Chloe 素材中，`Chloe_hair_back_01` 是当前确认的底座；`back_02/03` 更接近丸子或后部附件，不能独立使用；`back_04..09` 仍属于实验后发。男性 Colin 素材中，`base_01/02` 是必选底层，`back_01..05` 是可叠加的后脑发段，`back_06` 保留为已知不完整实验件；8 个刘海素材确实存在差异，但此前因为没有 base 且共用层级处理不完整，不能作为有效整体发型。

## 推荐生成顺序

组件候选应按下面顺序处理：

`演员头部锚点 → 必选 base → 后脑发段 → 侧发 → 前发/刘海 → 后部附件 → 接缝与耳朵检查 → 四视图像素化检查`

不能直接做任意 `front × side × back`。每个组合还需要记录性别、发型角色、深度层级、耳朵关系和是否允许替换完整底座。

男性刘海当前的主要问题不是资源不存在，而是深度层级：孤立的 `Colin_hair_bangs_08` 可以覆盖额头，但和共用侧/后发组装后会被壳体遮挡。因此男性刘海应先建立独立的前发深度校正和组合审查，再进入推荐池。

## h.art 式贴合流程的复用方向

可以复用之前处理发型时的思路，但将它明确成可重复流程：

1. 以演员头部和耳朵为唯一空间锚点，不以源发型原点为准。
2. 按 `base / back / side / bangs / attachment` 分层导入并分别校准位置、比例和前后深度。
3. 对需要遮盖头皮的完整后发壳做表面贴合；附件只做局部贴合，不能用附件承担整块头皮覆盖。
4. 对侧面设置像素补偿和白缝检查，最后再跑四方向、动画帧和 Gallery 预览。

这套流程适合组件随机化，但每个新组合都必须先成为独立候选，不能直接绕过审查进入随机池。

## 游戏运行时策略

组件随机化适合离线生成候选和扩充素材池；游戏运行时建议随机选择已经通过审查的“整体发型 bundle”，而不是让每个 NPC 临时拼接任意组件。bundle 可以保存为一个可复用场景或资源组合，内部仍记录 base、前发、侧发和附件对象。

世界生成时只需要用 `world_seed + npc_id` 得到稳定的 `hair_bundle_id`，再从已加载的 bundle 池中取资源。这个选择是 O(1)，NPC 之间共享网格、材质和纹理，不需要运行 Blender，也不需要重复计算几何贴合。

如果确实要运行时拼装，单个 NPC 的成本约为组件数 `k` 的 O(k)，当前 k 通常为 3～5；小规模 NPC 没问题，但会增加节点、材质和绘制调用。大地图应先按组合键缓存装配结果，远处 NPC 使用低模或像素/广告牌，避免每个 NPC 都创建独立发型节点。

因此推荐的产品路线是：

`组件随机化（离线） → 四视图/像素验收 → 固化为整体发型 bundle → 世界生成按 seed 选择 bundle`
