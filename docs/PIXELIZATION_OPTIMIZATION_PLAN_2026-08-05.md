# 3D 渲染到 2D 像素化优化方案

更新时间：2026-08-05

## 目标

在不改变 Actor V1 的动作、四向相机、脚底锚点和图层合同的前提下，改善 3D→2D 输出的像素化质量。当前目标不是让 AI 重新绘制角色，而是建立可复现的离线处理和比较方法，找出轮廓、调色板、透明边缘和帧间稳定性更好的方案。

## 已锁定的输入与输出合同

- 输入：同一份 Actor V1 Blender 渲染结果、同一组四向相机、同一组 8 帧采样。
- 输出：front/right/back/left，每方向 8 帧；最终候选为 64×64 RGBA。
- 注册：共享画布、脚底 y=60、共享帧索引；禁止逐帧紧裁切。
- 眼睛：继续使用已经选定的确定性眨眼版本；像素化实验不得重新生成或重绘眼睛。
- Godot：只接收通过验收的 SpriteFrames，不在运行时拼装或移动五官。

## 首轮 A/B 实验

### A：当前最近邻基线

256px 参考渲染直接使用最近邻缩小到 64px。它保留形状和颜色，但容易出现锯齿、色阶跳变和细节消失，作为所有比较的基准。

### B：固定注册框 + 两阶段缩小 + 全局调色板

先在离线处理器中将 256px 输入缩小到 128px，再最近邻缩小到 64px；对四方向、全部 8 帧共享一张固定调色板进行量化，避免每帧独立量化造成闪烁。第一轮不加自动轮廓，不做逐帧裁切。

### C：Blender 原生像素化节点候选

在 Blender 合成器中验证 `Scale → Pixelate → Scale` 和 `Closest` 纹理插值，保持相机、动作采样和 pass 不变。C 只有在渲染结果可与 A/B 对齐时才进入 gallery。

## 质量指标

每个候选输出 manifest 和 QA 报告，检查：

1. 方向和帧数是否为 4×8。
2. 尺寸是否为 64×64，alpha 是否为二值或明确受控。
3. 四方向注册框、脚底位置和主体 bbox 是否稳定。
4. 全部帧是否使用同一调色板，避免颜色闪烁。
5. 轮廓是否可读，眼睛、耳朵、手脚是否被量化吞掉。
6. 眨眼序列是否仍为 `open → half → closed → half → open`，身体帧不被改变。

硬性失败包括：缺帧、方向错位、逐帧裁切、调色板漂移、透明边缘出现半透明噪点、或眼睛/脚底锚点改变。单纯“更像滤镜”不算通过。

## 工具选择

- 首先使用仓库内 Python/Pillow 处理器和 skill 提供的 palette/QA 逻辑，保证无外部 Blender 插件依赖也能复现。
- Blender 原生 Pixelate 作为第二候选，用于验证 3D 合成阶段是否能减少后处理损失。
- 2DFactory、Pixel Art Rendering、Pribambase 只作为外部 A/B 候选，不进入当前主流程；需要实际兼容性和授权确认后再试。
- Blender MCP 只做本地批处理编排，不进入像素质量合同。

## 实施顺序

1. 在当前分支建立 A/B 处理器和统一 manifest。
2. 使用已验证的确定性眨眼四向 8 帧渲染做首轮 A/B，并生成 contact sheet/GIF。
3. 运行像素 QA 和 Godot headless 基线，人工通过 Tailscale gallery 比较。
4. 选出稳定候选后，再实现 Blender 原生 Pixelate 候选。
5. 只有候选通过人工复核，才替换正式 runtime 输入；否则保留为 review-only。

## 当前阶段结论标准

首轮不追求一次完成最终像素美术，先证明“固定注册 + 全局调色板 + 可复现 QA”比当前最近邻基线更稳定。若 B 无法明显改善而 C 能改善，再将像素化前移到 Blender 合成阶段；如果两者都不能通过，回到 3D 相机、灯光和轮廓 pass 调整，不用 AI 插帧或重新生成角色。
